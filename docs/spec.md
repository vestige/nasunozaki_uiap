更新日: 2026-09-19

この文書には、開発を進めるために必要な設計概要、確定事項、安全境界、未完了TODOだけを記載する。
調査の時系列や完了作業はGit履歴とIssue、詳細な動作結果はテストと診断ログで管理する。
コード開発モードとAWS上のC/C++ビルド基盤は [`spec_build.md`](spec_build.md) を参照する。

## 1. プロダクト概要

UIAPduinoのプログラム作成、実行、状態確認、保存、実機への書き込みをブラウザから行える開発環境を作る。

入口は次の2つに分ける。

1. **ブロック開発モード**: 初学者・ワークショップ向け。Blocklyから安全な中間命令列を作り、画面シミュレーターまたは教育用ランタイムで実行する
2. **コード開発モード**: C/C++利用者向け。ブラウザ上で編集、build、生成物確認、書き込み、verifyを行う

両モードで対象デバイスの識別、安全確認、診断ログ、backup・verifyの下位機能を可能な範囲で共有する。

## 2. 現在の構成

```text
Blockly workspace
      ↓
安全な中間命令列
      ↓
Execution Engine
      ↓
BoardAdapter
  ├── 画面シミュレーター
  └── 教育用ランタイム（WebHID）

コードエディター
      ↓
Web Build
      ↓
生成済みfirmware
      ↓
bootloader（WebHID）
```

Blocklyは現在、Arduino C/C++や`.bin`を生成しない。ブラウザ内で作った中間命令列を逐次実行する方式であり、ブラウザを閉じた後のボード単独実行には未対応である。

教育用ランタイムの通常命令と、bootloaderによるflash操作は別経路・別Adapterとして維持する。

## 3. 現在使える機能

- BlocklyによるLED点灯・消灯、待機、回数指定の繰り返し、「ずっと」の継続実行
- Blockly作品のブラウザ内自動保存と`.uiap.json`入出力
- 画面シミュレーターとUIAPduino実機の実行先切り替え
- 実行中ブロックのハイライト、停止、USB切断時の終了処理
- 教育用ランタイムによる内蔵LED操作
- D5（PC3）に接続した外付けタクトスイッチの読み取り
- 「もし タクトスイッチが押されている なら／でなければ」条件ブロック
- 画面上で操作できるタクトスイッチと固定配線ガイド
- bootloader・通常動作モードの識別と診断ログ
- 完成済み教育用ランタイムのブラウザ書き込み
- ローカルのC/C++ Web Build試作

## 4. 初期教材の確定仕様

### 4.1 タクトスイッチ

- 小型ブレッドボードを使用する
- 外付けタクトスイッチをD5（PC3）とGNDの間へ固定配線する
- D5は教育用ランタイムで`INPUT_PULLUP`として扱う
- 基板上のリセット／boot切替ボタンは教材の入力に使わない
- 子ども向けUIではLOW/HIGHや生のピン番号ではなく「押されている／押されていない」と表示する
- 「タクトスイッチを使う」を選ぶと、固定配線ガイド、画面上のスイッチ、条件ブロックを有効にする
- 配線ガイドではUIAPduinoを左右各12ピン、ブレッドボードを12行で表示する。タクトスイッチは、足をH字に少し広げて縦置きにし、横3列を使う
- 配線ガイドではD5をスイッチ上側、GNDを下側の接点へ固定配線し、上側／下側の各2本が常時導通、押下時のみ上下が導通することを示す
- 画面シミュレーターでは、スイッチを押している間だけ押下状態にする
- 実機ではランタイムcommand `0x02`で押下状態を読む

### 4.2 最初の課題

```text
もし タクトスイッチが押されている なら
    LEDをつける
でなければ
    LEDをけす
```

初回チュートリアルでは固定配線を使い、自由なピン選択や汎用回路シミュレーションは提供しない。

## 5. 通信と対象デバイス

| 用途 | VID:PID | 主なReport |
| --- | --- | --- |
| bootloader | `0x1209:0xB803` | Feature Report ID `0xAA` |
| 教育用ランタイム | `0x1209:0xD004` | Report ID `0`、8バイト命令・応答 |

教育用ランタイムの8バイト形式:

| byte | 内容 |
| ---: | --- |
| 0〜3 | ASCII `UIAP` |
| 4 | protocol version `0x01` |
| 5 | command。応答時はbit 7を立てる |
| 6 | sequence |
| 7 | payloadまたはstatus |

初期command:

- `0x01`: 内蔵LEDのON/OFF
- `0x02`: D5タクトスイッチの状態読み取り

## 6. 対応環境

- デスクトップ版ChromeまたはEdge
- HTTPSまたはlocalhost
- WebHID対応環境

Safari、Firefox、スマートフォンは現在対象外。Chromebookは実機検証待ち。

## 7. 安全境界

- WebHID選択画面は用途ごとのVID/PIDで絞り、他のHIDデバイスへ命令を送らない
- Blockly workspaceをJavaScriptとして直接評価しない
- 子ども向けブロックから任意GPIO、任意I2C payload、任意メモリアドレスを送らない
- 通常動作ランタイムからbootloaderのflash操作へ到達させない
- flash書き込み前に対象、範囲、backup、verify、復旧手段を確認する
- 過去に先頭64バイトのeraseで先頭4バイトだけが`0xFF`になったため、原因確定まで同じerase試験を再実行しない
- 保存済みbinからの直接復元成功を、erase経路の安全確認完了とは扱わない
- 診断ログとBlockly作品をサーバーへ自動送信しない

## 9. 開発運用

- 1つの利用者価値または検証項目を1 Issueにする
- 実装はIssueごとに`codex/<短い名前>`ブランチを作る
- Pull Requestには目的、画面確認、テスト結果、残課題を記載する
- 完了した作業一覧をこの文書へ蓄積せず、IssueとGit履歴へ残す
- 設計の確定事項または優先TODOが変わった場合だけ、この文書を更新する
- 大きな調査結果は`docs/`の専用文書へ分離し、この文書からリンクする
