# 色をおぼえる・差し込む（#62）

## 目的と順序

#41の色の値入力を実装する。#61のカラーバーを土台に、色ブロック→既存変数→NeoPixelの色入力の経路を追加する。ブラウザ、実機プレビュー、ボード保存の対応までを今回の範囲とする。分類ごとの学習サンプルは、その後の仕上げへ分ける。

カラーバーは`codex/neopixel-color-bar`の`9441437`で区切った。作業ブランチ`codex/62-neopixel-color-values`はこのコミットから分岐しているため、#61に依存する。カラーバーと今回の変更は別の差分としてレビューできるようにする。現在どちらもpush・PRは未実施。

## UI案

- 「色［カラーバー］」という値ブロックをNeoPixel分類へ追加する。
- 「［めも］に［色］をおぼえる」「［めも］のなかみ」は既存の変数ブロックを使う。
- 全灯・個別点灯の色欄を差し込み口とし、初期状態では色ブロックのshadowを置く。使い始めは今と同じクリックでカラーバーを開き、発展時に色変数を差し込める。
- 新しい色入力ブロックを追加し、旧固定色ブロックは読み込み・変換経路を維持する。移行する際は固定色、明るさ、番号、接続を失わないことをテストする。

## 値の扱い

色は6桁RGBを持つ独立した型とし、数字と混同しない。変数は数値・真偽値・色のいずれかを保持する。色同士の等しい／等しくない比較を許可し、異なる型の等価比較は既存ルール（等しい=false、等しくない=true）へ合わせる。色の大小比較・加減算・論理演算・条件への直接利用は拒否する。

NeoPixelの色入力は色型のみを受け付ける。未初期化・不正RGB・数値や真偽値の誤差し込みを拒否して安全停止する。明るさ0%でも入力の型検証を省かない。

## 保存形式案

作品ファイルは新しいブロックに対応するversionへ更新し、既存形式の読み込みを維持する。ボードbytecodeは形式6を候補とする。

- 色の式は新しいタグとRGB3byteで表現する。
- ファームのValueは既存32bit値領域に24bit RGBを格納し、新しい型タグで数値と区別する。変数の静的RAM領域は増やさない案。
- NeoPixelの新命令は対象LEDの値（または全灯）、色の値、明るさの値を持つ。定数だけなら既存の小さい命令へ変換できるか検討する。
- 構造検証と実行時の型検証を維持し、旧ファームにはBEGINより前の対応照会で更新を案内する。
- bytecode番号や正確な符号化は既存命令との衝突がないことを確認して実装時に確定する。

## 容量・確認

基準は#52のbin12,108 / 14,336 bytes、静的RAM440 bytes。追加前後を同条件で測定し、二重bank・payload992・深さ8・安全停止は変更しない。

色の変換、型、条件分岐、短絡評価、保存復元、旧作品、新形式の消去前照会、不正値、安全停止をテストする。確認作品は色を変数に覚え、同じ変数から全灯・個別点灯へ渡す短い構成とする。実機では通常プレビュー、保存、再給電、実行中更新を確認する。

## 実装状況（2026-10-11）

色の値ブロックと全灯・個別の色入力ブロックを追加し、NeoPixel一覧へ配置した。既存の固定色ブロックは自動置換せず、読み込み・実行経路を維持する。新しいブロックを一覧から使うと色のshadowをカラーバーで選べる。既存のおぼえる／なかみを使って色を保持できる。

Webの値表現にはcolor型を追加し、内部でRGB文字列を扱う。ファームは既存Valueの型タグ3で24bit RGBを保持する。式タグ15＋RGB3byte、opcode0x34＋対象種別0/1＋個別なら番号の式＋色の式＋明るさの式を保存形式6に追加した。色と明るさの型を実行時に検証し、0%でも誤った色型を拒否する。形式1〜5の命令は維持し、色機能なしの旧作品は以前の形式で保存する。新色入力命令は定数だけでも今回は形式6を使い、定数畳み込みは行っていない。

作品ファイルはversion7へ更新し、形式1〜6の読み込みを維持。古いボードには形式照会で保存開始前に更新を案内する。WebHIDのRGB送信方式は変更しないため、ブラウザからの色変数のプレビューには新しい通信命令は不要。単独実行には形式6対応ファームが必要。

ビルドはbin12,416 / 14,336 bytes、空き1,920 bytes。#52の基準から308 bytes増、静的RAM440 bytesで増加なし。配布ファーム・メタデータ・ZIPと実機はまだ変更していない（試作ソースと配布物は未同期）。

[色をおぼえる確認作品](../examples/blockly/neopixel-color-memory.uiap.json)は青系とピンク系をいろ変数へ順番に覚え、全灯を約1秒ずつ3回切り替え、最後に消灯する。変数から全灯・個別へ渡す実行、不正色・未初期化・誤った型の拒否、色の比較、禁止演算、保存復元、C++実行、旧形式拒否と消去前照会を自動テストする。見た目・実機動作・保存／再給電の確認はこれから行う。

ユーザーが画面で青系・ピンク系の3回の切り替えを観測したが、暗い背景で色を判別しにくいと報告した。NeoPixel表示部分を白地・濃い文字へ変更し、消灯は薄い灰色にした。点灯時のRGBと明るさの計算は変更していない（15%の画面色は引き続き暗くなる）。実機の色・明るさ・命令は変更しない。変更後の判別しやすさは確認待ち。

追記: 白地へ変更しただけでは、実行時のRGB×15%により点灯色がほぼ黒に見えるとの報告を受けた。画面プレビューの状態をRGBと明るさに分離し、色見本は指定RGBのまま表示、明るさは%表示と光彩で示す。消灯は薄い灰色と「―」。画面上の発光強度を物理的に再現する表示ではなく、選択色の判別を優先する。実機送信・保存命令は変更しない。15%の青系・ピンク系の色保持と0%・消灯の表示状態に回帰テストを追加した。

ユーザーが新しいプレビュー表示を見やすく判別しやすくなったと確認した。全273件のテストを確認。ユーザーの書き込みモード接続後、形式6対応の12,416 bytesの試作ファームを実機へ書き込み、全12,416 bytesの読み戻し照合とアプリ起動が成功した。色変数作品の実機動作・保存／再給電はこれから確認する。配布物はまだ更新していない。

追記: 通常接続で`neopixel-color-memory`を実機実行し、青系とピンク系を約1秒ずつ3回切り替えて消灯する想定どおりの動作をユーザーが確認した。続けてボードへ作品を保存し、USBを抜き差しした後もブラウザの実行操作なしで同じ動作が再開・終了することを確認した。色の代入・参照から全灯へ渡す通常プレビュー、保存・再給電後の単独実行を実機確認済みとする。個別LEDへの色変数入力と誤った色型での安全停止は自動テスト済みだが、実機確認はまだ行っていない。配布物は未同期。
