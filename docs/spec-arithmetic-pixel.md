# 足す・引くとNeoPixelの番号入力（#50）

## UIと互換性

- 「おぼえる」に `［数］＋／−［数］` を追加。初期値は0と1の編集可能なシャドーブロック。
- NeoPixelの個別点灯ブロックの番号は、初期値1のシャドーブロック。数値・変数・計算を差し込める。
- 番号は利用者向けに1〜8。ブラウザの出力Adapterへ渡す直前に0〜7へ変換する。単独実行命令は1〜8で扱う。
- 作品ファイル／自動保存の形式を4へ更新。1〜3は引き続き読み込む。旧 `uiap_neopixel_set` のPIXEL欄を新ブロック `uiap_neopixel_set_value` の数値入力へ移行し、色・明るさ・接続・位置は維持する。元のJSONを変更しない。
- 旧ブロックの登録と変換処理は直接Blocklyデータを読み込む経路のために維持。画面の一覧には新ブロックだけを出す。
- 正常な数値リテラルの番号は従来の固定番号命令へ変換し、不要なファーム更新を要求しない。色・明るさの値入力は今回対象外。

## 数値と安全性

加減算の入力と結果は符号付き32bit整数（−2147483648〜2147483647）。画面・ブラウザからの実機実行・単独実行で共通とする。小数・真偽値・範囲外数値は計算に使わない。結果を黙って丸めたり整数を周回させたりしない。

動的LED番号は実行時に整数1〜8を検証する。未初期化変数、型不正、0・9・負数などを検出したら後続命令を停止する。固定の不正番号や空入力は変換時にも検出する。ブラウザ実行のセッション終了処理とボードの既存終了処理が消灯を担当する。

式／構造の深さ8、変数16個、payload992バイトの制限は維持。加減算は演算順が重要なので、論理演算のような平衡化は行わない。

## 単独実行形式3

header・CRC・二重bank・更新手順は従来通り。既存命令だけなら形式1／2を使い、新命令が1つでもあれば形式3を要求する。後続の形式2命令で要求形式を引き下げない。

| 追加 | 形式 |
| --- | --- |
| 式13 | ADD、後続に左式・右式 |
| 式14 | SUB、後続に左式・右式 |
| 命令0x31 | LED番号の式、R/G/B各1byte、明るさ1byte |

形式3では命令0x30の固定番号指定も維持。新しい式／命令は形式1／2では拒否する。対応問い合わせは0x53を返し、ブラウザはBEGIN前に形式3対応を確認する。形式2までのファームでは消去や実行停止を行わず更新案内を出す。

ファームの加減算はコンパイラのoverflow検出組み込み関数を使い、符号付き整数の未定義動作を避ける。整数の境界、型不正、範囲外番号、命令の途中切れをサニタイザー付きホストテストで確認する。
