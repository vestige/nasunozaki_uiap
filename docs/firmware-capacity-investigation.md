# ファーム容量調査（#52）

## 現在の結論

旧埋め込み方式の廃止後、明るさ入力・圧電スピーカーが追加され、空きは96 bytesになっていた。2026-10-11、ランタイム専用の時刻計算で **2,132 bytes削減、bin12,108 bytes、空き2,228 bytes、静的RAM440 bytes** を確保した。予定した実機回帰確認を経て、配布物を確認済み版へ同期した。CRC共通化の試作（48 bytes削減）は今回採用していない。以下の過去段階の「未実施」「これから」は履歴である。

## 時刻計算の小型化試作（2026-10-11）

利用者の続行指示を受け、`runtime_clock.h`にArduino依存のない`RuntimeClock`を追加した。coreのmillis/microsやインストール済みcoreは変更しない。ランタイム内の5つのmillis呼び出しだけを`runtimeMillis()`へ置き換え、48MHz SysTickのカウンタを入力する。48MHz以外のビルドはstatic_assertで拒否する。toneの期限サービスでは発音していない間も時刻を読み、通常のmain loopと待機中に継続更新する。

### 計算と制約

- 状態は直前の32bitカウンタ、32bitミリ秒、1ms未満の端数tick（各uint32、計12 bytes）。初回はカウンタのゼロからの経過を扱い、既存coreの初回読み取りと一致させる。
- 48,000で割った商と余りを別々に加える。`delta + remainder`を先に計算すると32bit上限であふれるため、その形は使わない。余りの和は95,998以下で、1msの繰り上がりだけを処理する。
- SysTick差分とmillis加算は符号なし周回を利用する。長期の累積tickを32bitへ単純に切り詰める方式ではない。
- 既存core同様、呼び出し間隔はSysTickの1周（約89.5秒）未満が必要。1周以上の未読期間では周回数を復元できない。通常のランタイムは命令・待機ごとに通信サービスを処理するが、デバッガ停止等は保証しない。
- main loop専用。割り込みからの再入、他ライブラリのmillis/microsとの状態共有には対応しない。現状の使用ライブラリから汎用millisへのリンク依存が残らないことはELFで確認した。将来依存が増えたら再測定する。

### テスト・実測

同じビルド条件でbin **12,108 bytes、空き2,228 bytes、静的RAM440 bytes**。配布基準からFlash2,132 bytes削減、RAM4 bytes削減。CRC共通化は含めていない。.init160、.text11,928、.init_array4、.data16、.bss424 bytes。試作bin SHA-256は`60714c31f58a81f4759d84c748c4e6eec487e57c1b5581819a0d2a7ba3b7c73c`。

ELFから`__udivdi3`（1,884 bytes）と`__clz_tab`（256 bytes）が消えた。最終削減量との差8 bytesは置換処理・配置の差を含む。PWM、USBサービス、VMのrange/expr、NeoPixel::showのシンボルサイズは基準と同じ。関数サイズの一致だけで時間的動作が同じと保証するものではない。

`runtime_clock_host.cpp`をC++の警告エラーとAddress/Undefined sanitizers付きで実行し、64bit累積tickによる基準と比較した。ゼロ・遅い初回、同一時刻の再読、48,000前後の端数、最大差分、SysTick周回、millis周回、10万回の固定seed差分を確認。既存テストを含め **249件／40ファイル成功**。これは時刻計算の算術検証で、実機のクロック設定、音の長さ、USB応答時間、長時間耐久を観測したものではない。

### 採用前の次の確認

試作ソースは調査ブランチに保持し、配布bin・build-info・ZIPは基準版のままとする。そのためこの段階のソースと配布物は未同期で、packagingのハッシュ検査は一致しない。採用して配布する際は新ヘッダーもハッシュ検証・ZIP同梱へ追加する。

次に利用者の了承を得て実機回帰を行う。音階・指定時間・途中停止、スイッチ長押しと再押下、NeoPixel、保存・再給電・演奏中更新、不正作品の安全停止、少なくともSysTick周回をまたぐ運転を確認する。確認前に実機へ書き込んだり配布物を更新したりしない。長時間耐久・スタック高水位は別途未測定として扱う。算術テストと容量の結果からは、作品形式・通常保存の仕様を変えずに余裕を確保できる有力候補になった。

### CRC共通化の測定

`standaloneCrc16(offset, length)`を一時的に削除し、起動時検証も既存の`updateCrc16(volatile pointer, length)`を呼ぶ形へ変更した。初期値0xffff、多項式0x1021、volatile読み出し、対象範囲は維持。クリーンビルドで48 bytes減、RAMは不変。試作bin SHA-256は`1f5d3afc668a12407db829e0f14baddbfe5f6253a2018383fcae859aded11ad9`。

この試作は容量測定のみで、変更版のCRC回帰テスト・実機検証は行っていない。採用せずソースを元に戻した。採用する場合はCRCの既知ベクトル、volatile領域・長さ境界、bank選択、通常更新と不正CRC拒否をテストする。削減効果は小さいが、重複を減らす候補として有効。

### 次に試す順序と判断条件

1. **時刻計算の小型化を独立して試作する。** coreの`wiring_time.c`は48MHzのSysTick差分を64bitへ累積し、millisで48,000による64bit除算を行う。逆アセンブルでも`__udivdi3`への呼び出しを確認した。単に累積tickを32bitへ置き換えてはいけない。msと端数tickを分けて保持する方式などを検討し、端数の累積、SysTick周回、millis周回、最大差分、初期化、繰り返し呼び出しのテストで基準と比較する。48MHzの32bit SysTickは約89.5秒で周回するため、長い未読期間の扱いも定義する。既存coreも呼び出し間隔が1周以上になると周回数を復元できない。
2. **coreを直接編集せず再現可能にする。** ランタイム専用の時刻処理で依存を切る案と、管理されたcoreパッチを比較する。他のライブラリにmillis/microsの依存が残れば除算関数は消えない。APIとビルドの再現性、RAM・速度の増減も測る。1,884+256 bytesがそのまま空くとは保証しない。
3. **削減候補ごとに自動テストと実機回帰を行う。** 音の期限・手動停止・保存作品の待機、スイッチ判定、NeoPixel、USB応答、通常保存・再給電・実行中更新、不正値の安全停止を確認してから採用する。配布物の同期と実機書き込みは、その採用判断後。
4. **CRCは別差分で扱う。** 時刻処理と同時に変えて原因を混ぜず、48 bytesという実測を基に採用を判断する。

今回は機能や旧形式を削らず、14KiB上限・末尾2KiBの二重bank・payload992 bytes・安全検証を維持する。新しい色表現や#58の継続入力の増分は、それぞれ最小試作の前後差分で見積もる。次の修正用余裕を含む許容容量は試作結果を見て決め、空き96 bytesのまま追加機能を積み重ねない。

## 優先する削減候補

1. **旧bin埋め込み方式の廃止可否を決める。** 現在は有効なbankがない場合に旧領域へフォールバックする。通常接続で保存する二重bankは別なので維持できる。予約領域自体は1,024 bytesだが、最終削減量はビルドで測る。Web側の旧bin生成・復旧経路、テスト、配布説明を併せて調べてから変更する。旧方式が使えなくなるため、承認前には削除しない。
2. **CRC実装の共通化を試す。** standaloneCrc16とupdateCrc16に同じ多項式のループがある。volatile読み出しと対象範囲を維持して共通化し、更新・起動時検証のテストとbin差分を比較する。LTOが既に最適化している可能性があり、削減量は未測定。

変更版で通常接続から順方向作品を保存し、利用者が1→8→1の点灯を確認。再給電後もブラウザ操作なしで同じ動作を再開した。続けて実行中に逆方向作品へ更新し、8→1→8への切り替えと、再給電後も逆方向で再開することを利用者が確認した。範囲外LED番号と計算の桁あふれの安全停止作品をそれぞれ保存し、いずれも利用者が最終的な全消灯を確認した。過渡的な発光を計測したものではない。

タクトスイッチのトグル作品を保存し、1回押すと点灯、長押し中は維持、離して再押下すると消灯することを利用者が確認した。点灯中にブラウザからのボード実行へ切り替え、利用者が再び点灯させた後に「とめる」を実行。画面の停止表示と、利用者による実機の全消灯を確認した。

保存中断後の復旧と空bank起動の実機結果は以下。COMMIT中の瞬断は今回のDATA途中の中断とは区別する。

保存中断テストでは開発用bank-check.htmlからSTATUSで有効bank Bを確認し、非アクティブ側へBEGINとヘッダ16バイトのDATAだけ送信した。COMMITは送信しなかった。その状態から利用者がUSBを抜き差しし、元のタクトスイッチ作品で点灯・消灯を切り替えられることを確認した。これによりDATA途中の切断後の復旧は実機確認済み。COMMIT中の瞬断は未確認。

空bank画像の全領域verify後、通常画面でWebHID接続が成功し、トグル作品を保存できた。利用者が押すたびの点灯・消灯と長押し中の維持を確認した。消去した作品の復元は完了。STATUSの空bank値は別途採取していないため、空状態の根拠は0xffの画像と全領域verifyである。

予定した実機回帰確認は完了。残作業は配布bin・メタデータ・ZIPの同期、説明の最終整理と自動テストの再実行。長時間耐久、COMMIT中の瞬断、スタック高水位は未検証のまま残す。容量削減は1,056 bytes、空き1,380 bytesであり、追加機能が収まることまでは保証しない。
