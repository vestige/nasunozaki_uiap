## 現在の結論

旧埋め込み方式を廃止して1,056 bytes削減し、空き1,380 bytesを確保した。予定した実機回帰確認と作品復元を完了し、配布bin・メタデータ・ZIPを検証済み版へ同期した。以下の「未実施」「これから」は各調査段階の記録で、最新の確認結果は末尾の実機記録を参照。CRC・時刻処理の小型化、追加機能の容量試作は今後の候補として残す。

## 基準測定：2026-10-10

対象はmainの `67e799a`（#51マージ後）。調査ブランチは `codex/firmware-capacity-investigation`。
`./scripts/workshop-runtime.sh build` で再測定。実機への書き込み、配布binの更新、coreのコード変更は行っていない。

- core UIAP_HID 1.2.14、GCC 14.2.0-2、48MHz HSI、WebHID、Os + LTO。

## 優先する削減候補

1. **旧bin埋め込み方式の廃止可否を決める。** 現在は有効なbankがない場合に旧領域へフォールバックする。通常接続で保存する二重bankは別なので維持できる。予約領域自体は1,024 bytesだが、最終削減量はビルドで測る。Web側の旧bin生成・復旧経路、テスト、配布説明を併せて調べてから変更する。旧方式が使えなくなるため、承認前には削除しない。
2. **CRC実装の共通化を試す。** standaloneCrc16とupdateCrc16に同じ多項式のループがある。volatile読み出しと対象範囲を維持して共通化し、更新・起動時検証のテストとbin差分を比較する。LTOが既に最適化している可能性があり、削減量は未測定。
3. **時刻処理の小型化を別途検証する。** 逆アセンブルでmillisから__udivdi3への呼び出しを確認。coreのwiring_time.cは64bitの累積tickを使う。単に32bitへ置換すると周回・長時間待機・チャタリング判定を壊すおそれがある。代替方式、周期境界・長時間のテスト、coreへのパッチ管理が必要。1,884 bytesがそのまま空くとは限らない。

Os + LTOは既に有効。最適化設定だけで大きく減るとは期待しない。USB波形、NeoPixel波形、Flash更新、不正値検証を無条件に短縮・削除しない。

## 追加機能の見積もり方法

明るさ・色・ブザーの必要バイト数は未測定。根拠のない数値は置かず、削減後の基準版に最小試作を1機能ずつ追加してbin、静的RAM、シンボル差分を採る。

- 明るさ：既存の数値式評価を再利用できるか、範囲検証と新命令の増分を測る。
- 色：色の表現を先に決める。パレット番号とRGB値では必要な変換処理が異なる。
- ブザー：使用PIN・タイマー・停止方法を決める。既存PWMコードの再利用、USB／NeoPixelとの同時動作への影響も調べる。一般的な並列実行機構とは分けて見積もる。
- 各試作は14KiB以内だけでなく、次の修正用の余裕を確保できるか比較する。安全チェック、二重bank、作品容量は維持。

## 旧方式廃止の試作結果

利用者の続行指示を受け、旧予約領域とフォールバック、Webユーティリティの埋め込み関数、専用bin生成スクリプトを削除した。スクリプトはGit履歴から復元可能。通常接続の二重bank、payload上限992、命令形式1〜3の対応は維持する。作品未保存／両bank無効の場合はポインタをnullとし、自動実行せず待機する。検証関数にもnullガードを追加した。

- 同じ条件でbin **12,956 bytes、空き1,380 bytes**。基準から1,056 bytes削減。
- 静的RAM **432 bytes**。基準より4 bytes増加（静的配置の変化を含む。スタックは未測定）。
- 自動テスト180件成功。旧埋め込み専用テスト2件を削除したため182件から減少。Web・ファームのビルド成功。
- 通常保存の画面に埋め込み関数の呼び出しはなく、操作UIの変更は不要だった。
- 実機への書き込み、配布bin・メタデータ・ZIPの更新は未実施。現時点ではソースと配布物が異なるため、配布前に必ず同期する。

次は有効bankなしの待機、通常保存、再給電、自動実行、bank切り替えと不正作品の安全停止を変更版で確認する。旧埋め込みだけで保持していた作品は自動移行しないため、元の作品ファイルから通常接続で保存し直す必要がある。CRC共通化・時刻処理・追加機能の容量試作はまだ行っていない。
