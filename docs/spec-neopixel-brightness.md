# NeoPixelの明るさへの値入力（#54、親 #41）

## 仕様

全灯と個別点灯の両方で、明るさに数値・変数・加減算を差し込む。初期値20の数値シャドーを表示し、ブロックを差し込まなくても直接編集できる。単位は%。色は既存の選択欄を使う。普段の明るさは15〜20%を目安とし、20%を超える設定も可能だが、教材・サンプル・実機確認は20%以下にそろえる。

明るさは整数0〜100。0は消灯として扱う。旧作品の明るさは1〜100なので、そのまま同じ結果になる。小数、未初期化、真偽値、範囲外値、演算の桁あふれは実行を停止し、既存の終了処理で消灯する。定数なら変換時、変数・計算なら実行時に検証する。

## 互換性

新ブロック種別で明るさ入力を持たせる。旧種別は引き続き登録して直接読み込みにも対応し、通常のファイル・自動保存読み込みでは旧BRIGHTNESSフィールドを数値シャドーへ変換する。移行処理は元JSONを変更せず、個別点灯のPIXEL入力、色、位置、nextを維持する。保存形式は5へ更新し、1〜4の読み込みを維持する。

固定の明るさ1〜100なら従来の中間命令へ最適化する。固定0は色を黒、明るさを従来命令で許可される値として出力すれば、対象LEDだけを消灯できる。全灯と個別LEDの対象範囲を維持し、個別の0%を全消灯へ置き換えない。

## 単独実行の案

新しい式そのものは不要。既存の数値・変数・算術式を再利用し、動的明るさの命令だけ追加する。

- 形式4を追加し、能力問い合わせを0x54へ更新する。
- 新命令は「対象指定＋RGB＋明るさの式」。全灯と個別点灯を扱い、個別点灯では既存の動的LED番号を併用可能にする。
- LED番号と明るさの検証完了後にのみ出力し、不正な値で一部だけ点灯することを避ける。
- 静的な作品の形式1〜3は維持する。新形式の保存はBEGIN前に能力を照会する。
- 形式要求は命令を処理する順番で引き下げない。

## 検証と容量

基準は #53 の12,956 / 14,336 bytes、空き1,380 bytes、静的RAM432 bytes。実装後に同じcore・最適化条件で測る。容量が増えても作品用2KiBと二重bankを維持する。

確認対象：全灯／個別、0・1・20・100%、変数と計算、動的LED番号との併用、旧固定欄の移行・復元、−1・101・小数・真偽値・未初期化・桁あふれ、形式未対応時に既存作品が残ること。

実機用作品は15→16→…→20%の段階変化と、15%／20%の比較にそろえる。20%超の出力は今回の目視試験対象にしない。

## 状態

実装と予定した実機確認を完了。通常接続の動的明るさ作品保存、再給電後の再実行、0%で8番だけ消灯することを確認した。範囲外101%の作品は15%で緑点灯・2秒待機後に安全停止し、後続の赤点灯を実行せず全消灯することを利用者が確認した。配布物は実機へ導入した同じbinへ同期する。以下は確認の経過である。

変数の0%を個別点灯の8番へ指定する確認作品を保存し、利用者が全灯の緑点灯後に8番だけ消えて1〜7番が点灯を保つことを確認した。保存後のブラウザ状態取得はタイムアウトしたため、保存完了の根拠は利用者の実機確認である。

ブラウザからの固定値比較作品（15%を3秒、20%を3秒、3回）で、利用者が後半の20%のほうが明るいことを確認した。最初の15〜20%の短い段階変化には「徐々に暗くなった」との報告があったため、動的値の実機合格はまだ扱わない。変数を増やす作品の待機を各3秒へ延ばし、単独実行でも確認する。

その後、待機を3秒にした変数作品を通常接続で保存した。保存確認後のブラウザ操作はタイムアウトし、画面の完了表示は取得できなかったが、利用者が「3秒ごとに少しずつ明るくなり、約18秒後に消灯」を確認した。ブラウザの「ためす」は押しておらず、新命令を使うボード単独実行の動作を確認できた。再給電後の自動実行は次に確認する。

利用者がUSBを抜き、ボタンを押さずに再接続した後も、3秒ごとに徐々に明るくなり約18秒後に消灯することを確認した。再給電後の自動実行も確認済み。

利用者の書き込みモード接続後、新ファームを公式手順で導入。13,256 bytesを13,312 bytesへパディングし、verify成功・アプリ起動・通常のUIAPduino WebHIDへの再列挙を確認した。bin SHA-256は `19026ae5a05a36ddf44a740d1c1f555b04aa7d881a5e5a02f8861036ebc49b01`。明るさ作品の目視確認は未実施。

明るさ入力と旧作品移行、保存形式5、ブラウザ実行、単独実行形式4を実装。命令0x33は対象モード0（全灯）／1（個別）、個別の場合の番号式、RGB3bytes、明るさ式を持つ。固定値は従来命令へ最適化する。

同じビルド条件でbin13,256 bytes（基準より300増加）、空き1,080 bytes。静的RAM432 bytesで増減なし。Web・ファームのビルドと回帰テストが成功。動的明るさと加減算を併用した確認作品で、要求形式が4から3へ下がる不具合を検出し、encodeValueでも形式を引き下げないよう修正した。実機への導入と目視確認は上記参照。
