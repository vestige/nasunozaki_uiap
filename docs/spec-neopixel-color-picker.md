# NeoPixelのカラーバー（#61）

## 範囲

#41の色入力の前段として、既存の固定色ドロップダウンを独自のBlocklyフィールドへ変更する。色を変数に覚えたり値ブロックとして差し込んだりする機能は別段階。ファーム、通信、保存bytecode、作品ファイルの形式は変更しない。

## 選び方

- 色欄を押すと、現在の色見本、よく使う8色、色相のカラーバー、あざやかさのバーを表示する。
- 色相は0〜360度、あざやかさは0〜100%。白から鮮やかな色へ調整する。発光の明るさは既存の明るさブロックに任せ、ここには追加しない。
- フィールドは6桁RGB（`#rrggbb`）を保持する。プリセットは名前、それ以外はRGB値を表示する。RGBからHSVを求め、バー操作時にRGBへ戻す。
- 既存RGB値は開くだけで変更しない。HSVのvalueも保持するが、黒からのバー操作はvalue=1で色を選べるようにする。無彩色から色相を変更すると、あざやかさ100%で選び直す。
- 8色ボタン、バー、できたボタンはキーボードで操作できる。Escapeとできたで閉じる。フィールド削除時も自身のポップアップを閉じる。

## 互換性と担当

`colorPicker.ts`は色の検証と変換、`colorField.ts`はBlocklyフィールドとポップアップDOM、`blocks.ts`は登録と各色欄の利用を担当する。React外へ表示されるポップアップのCSSは`uiap-color-*`へ限定する。

既存作品の`COLOR`名とRGB値、8色を維持する。任意の6桁RGBの保存・復元を許可し、不正値はフィールド検証で拒否する。従来のNeoPixel RGB送信・bytecodeのRGB3バイトをそのまま利用するため、ファーム容量は増えない。定数の明るさは既存の小さい保存形式へ変換される。

## 確認状況

RGB/HSVの往復、白・黒・任意RGB、色相端点、あざやかさ、不正値、Blockly保存・復元、画面実行のRGB引数、既存bytecodeへのRGB格納の自動テストを追加した。ブラウザの見た目・キーボード操作・実機での新色はまだ確認していない。既存の大きいWeb chunk警告は継続する。実機や配布ファームは変更しない。

全体の進捗は[#41](https://github.com/vestige/nasunozaki_uiap/issues/41)、今回の作業は[#61](https://github.com/vestige/nasunozaki_uiap/issues/61)を参照。

2026-10-11: ユーザーがカラーバーの見た目を確認し、通常接続したボードで設定した色と同じ色に光ることを確認した。さらに「ボードにかきこむ」で保存し、USBを抜き差しした後も同じ色で光ることを確認した。選択色の実機点灯と保存・再給電後の維持を実機確認済みとする。キーボード操作は未確認。画面の色と実物の色の精密な一致を測定したものではない。
