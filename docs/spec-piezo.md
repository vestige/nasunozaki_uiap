# 圧電スピーカー（#49）

## 現在の段階

最初の段階として拡張の追加・削除と準備タブを実装する。タクトスイッチとNeoPixelと同じレイアウトを使い、部品イメージと短い説明を表示する。現時点のイメージは配線図ではない。

型番・定格・配線PIN・駆動方式は未確定。準備中を明示し、音のブロック・画面の発音・実機通信・単独実行命令はまだ追加しない。ファームと配布物は変更しない。

拡張状態は自動保存と作品ファイルの`extensions.piezo`へ保存する。省略時はfalseとして扱う。今回は既存workspaceと命令の意味を変えず任意のタブ情報を追加するだけなので、作品形式5を維持する。音ブロックを追加する段階で移行・形式バージョン・旧ファームへの送信防止を改めて設計する。

## 次に決めること

- 部品の型番と定格、音階を出せる発振回路なしの圧電スピーカーかを確認する。
- GPIO直結の可否、保護抵抗や駆動回路の要否を確認する。
- D5（タクトスイッチ）、D8（NeoPixel）、内蔵LED、USBと競合しないPINを選ぶ。右側の配線のしやすさも考慮する。
- 波形生成は他の処理を長時間止めない方式を検討し、USB・NeoPixelへの影響とタイマーの競合を確認する。
- 「鳴らして次へ進む」と「鳴らして待つ」を区別する。待つ場合も通信と停止操作を処理する。
- 最初は単音。新しい音で前の音を置き換える案とし、和音・複数ブロック列の汎用並列実行は別の拡張とする。
- 起動・停止・エラー・作品更新時の消音、発音時間の上限、接続切断時の扱いを決める。
- 最新の配布ファームは13,256 / 14,336 bytes、空き1,080 bytes、静的RAM432 bytes（[明るさ入力の記録](spec-neopixel-brightness.md)）。追加機能の容量と動作は同じ条件で測り直す。

全体の構成と安全境界は[全体仕様](spec.md)、Web側の担当範囲は[責任分担](web-responsibilities.md)を参照する。
