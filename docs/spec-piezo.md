# 圧電スピーカー（#49）

## 現在の段階

拡張の追加・削除、準備タブ、音ブロックと通常接続での音プレビューを実装した。タクトスイッチとNeoPixelと同じレイアウトを使い、ブレッドボード配線図と短い説明を表示する。

型番・定格は未確定。寸法は再確認で直径約12mm・高さ約6mm、PKM13EPYH系を候補としている。D6/PC4・1kΩ直列の専用試験と通常接続での音・LED・NeoPixel同時動作を実機確認した。保存形式5の音命令を追加し、作品の保存と再給電後の自動演奏も実機確認した。

拡張状態は自動保存と作品ファイルの`extensions.piezo`へ保存する。音ブロックの追加に合わせ作品形式を6に更新した（準備タブのみの段階は5）。形式1〜5の読み込みを維持する。省略時でも音ブロックがあれば拡張を復元する。タブを外しても置いたブロックは消さない。音声オン／オフは作品に保存せず、ページを開いたときはオフにする。

## 画面での音の試作

- 「音」カテゴリに`uiap_tone`と`uiap_stop_tone`を追加。ド〜高いド（262〜523Hzの8音）、100〜5,000ミリ秒を選ぶ。任意周波数や値の差し込みは今回の範囲外。
- `tone` IRは周波数・長さ・待つかどうかを持つ。「おわるまでまつ」は中断できる待機、「次へすすむ」は即座に次の命令へ進む。既存のブロック列を複数並列に動かす機能ではない。
- Web Audioの単一の矩形波を低い固定ゲイン0.025で鳴らす（実際の音量は端末設定にも依存）。新しい音は前の音を止めて置き換える。時間での終了を音声クロックに予約し、停止・エラー・作品の終わり・編集画面の破棄ではノードとAudioContextを解放する。作品終了時は、残りの発音時間があっても消音する。
- 「画面の音をオンにする」を選び「画面でためす」を押したときだけ音声機能を開く。ミュートでも待機と他の命令は同じように動く。音声利用に失敗した場合はエラーを表示し、ミュートでの実行を案内する。
- 音の命令を含む作品は、条件の未実行側やループの中も検査して、LEDなどの先行命令より前にランタイムの音対応を照会する。旧ファーム・不正応答・timeoutでは開始せず、終了処理も旧ファームへ新しい音命令を送らない。保存時は形式5の対応を確認してから更新を始める。
- 担当は`blocks.ts`（ブロック）、`toolbox.ts`（一覧）、`program.ts`（IR変換）、`execution.ts`（順次実行）、`browserTone.ts`（画面の波形と寿命）、`useBlocklyExecution.ts`（音声資源の所有と終了処理）。

## 単独実行の音命令（2026-10-11）

保存形式5で以下を追加する。WebHIDのcommand番号とは別のbytecode名前空間であり、通信封筒のversionは1のまま。

| opcode | 引数 | 動作 |
| --- | --- | --- |
| `0x40` | 音番号0〜7、長さ1〜50（100ms単位）、待機0/1 | 前の音を置き換えて発音。待機1ならUSBと音の期限管理を処理しながら待つ |
| `0x41` | なし | 消音しD6 LOWへ戻す |

形式1〜4は変更しない。音のない作品は従来の最小形式で保存する。旧ランタイムは形式5に非対応なので、ブラウザはBEGIN（消去・実行停止）より前に拒否して更新を案内する。全体検証で音番号、時間、待機flag、命令長、入れ子を検査し、不正作品は先行出力も実行しない。

波形生成と期限管理は通常プレビューと共用し、追加タイマーやRAMバッファを設けない。「次へすすむ」は単一の音と順次命令の併行で、複数のブロック列を並列実行する機能ではない。作品の終了・中断・エラー・更新開始では既存の出力停止処理で消音する。USBを抜いても保存した作品は動き続けるため、USB通信切断と単独実行の停止を同一視しない。

ビルド成功: bin **14,240 / 14,336 bytes（空き96 bytes）**、静的RAM444 bytes。音プレビュー版から+220 bytes、RAM増加なし。64byte単位の書き込み長は14,272 bytesで作品領域の手前に収まる。作品bankのアドレス・容量、14KiBリンカー上限、安全ガードは変えない。容量の余裕は極小のため、今後の機能追加は整理または別の容量設計を先に検討する。

保存命令の変換・C++実行器・不正値／旧形式での拒否・待機の中断・旧ランタイムへの転送拒否を自動テストで確認。新ファームの実機書き込み、通常接続での音作品保存、再給電、実行中の停止・更新はまだ未確認。

### 基本機能の区切りと残る確認

- 準備タブ・配線図、音階と長さ、画面／実機プレビュー、保存・再給電、途中停止・演奏中更新、長押し入力との組み合わせまでを今回の基本機能の区切りとする。
- 短い押下の取りこぼしは#58へ分離した。
- 不正値の拒否・旧ファームの消去前拒否は自動テスト済み。発音中のエラー消音とブラウザ通信切断時の期限停止は、実機でも確認する。
- 長時間耐久、スタック高水位、型番不明の部品の定格保証は確認済みとしない。
- 容量削減は#49の機能確認後に別作業で扱う（空き96 bytes）。

## 導入時の設計・検証記録

### 実機試験の候補（2026-10-10）

ユーザーが寸法を再確認し、直径約12mm・高さ約6mmと判明。旧カタログのPKM13EPYH4002-B0（直径12.6mm・高さ6.9mm）が近い候補。ただし型番を確定した扱いにはしない。参照: [村田製作所の旧カタログ](https://www.murata.com/-/media/webrenewal/support/faqs/products/sound/sounder/char/sc0002/p37e.ashx?la=en)。

試験PINはD6 / PC4を候補とする。導入済みUIAP_HID core 1.2.14のCH32V003F4 variantとPWMminではTIM1 CH4。D5/PC3の入力、D8/PC6のSPI1、内蔵LEDのD2/PC0とPINは重複しない。タイマー競合とUSB・NeoPixel同時動作は実機確認前であり、確認済みとしない。

短時間の試験案は`D6 → 1kΩ（直列）→ 圧電部品 → GND`。1kΩ直列は出力の充放電電流を抑えるための試験上の選択で、型番不明部品への安全保証やメーカーの指定回路そのものを意味しない。メーカーの保護抵抗1〜2kΩの記述は、同資料の回路図と合わせて扱う。電源PINには接続しない。USBを外して配線し、確認前は通電しない。

最初は短い単音を出す専用試験で部品を確認し、その後に実行時の発音・停止・時間制限を実装する。coreの`tone(pin, frequency, duration)`は時間指定すると待機する実装なので、そのまま非同期の命令として採用しない。PWMminまたは同等のハードウェア波形生成と期限管理を検討する。

専用試験を[examples/piezo-smoke](../examples/piezo-smoke/README.md)へ追加。通常ランタイムとは別にビルドし、4kHz 200ms → 無音 → 440Hz 500ms → 無音 → 523Hz 500ms → 停止を1回だけ行う。発音中は内蔵LED点灯。TIM1 CH4だけで波形を生成し、loopで期限を管理してD6 LOWへ戻す。2026-10-10、既存と同じcore・board options・14KiBリンカーでビルド成功、bin 7,516 bytes、静的RAM244 bytes。これは別スケッチの値で、正式ランタイムへ追加した場合の増分を示さない。実機への書き込み・発音・作品領域保持はまだ未確認。

追記: 専用試験の書き込み・読み戻し照合が成功し、ユーザーが想定どおりの発音と停止を確認した。作品バンクの保持はまだ読み戻し確認していない。現在の専用試験ファームは通常のランタイムへ置き換える必要がある。

追記: 通常ランタイム（bin 14,020 bytes）の書き込みと14,080 bytesの読み戻し照合が成功し、起動した。通常のWebHID発音とLED/NeoPixel同時動作は確認待ち。ユーザーから今回の部品は極性がなく、ブレッドボードに挿したと確認されたため、＋表示を削除し、タクトスイッチ・NeoPixelと同じボード外観のブレッドボード配線図へ更新した。部品の2本の足を同じ接続列に挿して短絡しないよう、別々の横一列と1kΩ直列の接続を示す。これは別型番の部品まで極性なしと断定するものではない。

## 通常ランタイムの音プレビュー

共通の8バイトUIAP envelope/version 1を維持し、以下を追加した。

| 命令 | payload | 動作 |
| --- | --- | --- |
| 0x33 | 0 | 音対応を読み取り、0x61で対応を通知する。出力・Flashは変更しない |
| 0x30 | 0〜7 | 次に鳴らす音の選択。すでに鳴っている音は変えない |
| 0x31 | 1〜50 | 選択した音をpayload×100ms鳴らす。以前の音を置き換える |
| 0x32 | 0 | 即座に消音しD6 LOWへ戻す |

TIM1 CH4のPWM波形はUSB/NeoPixelの割り込みに依存しない。期限管理はloopと単独実行中のサービス処理で行い、millis差分でwrapを扱う。起動、出力停止、作品更新開始、エラー応答で消音する（READ_BUTTONの押下値1をエラーと誤認しない）。作品更新中の発音は拒否する。接続切断で停止命令を届けられなくても、最後に受けた音は最大5秒で止まる。USB切断の瞬間の停止を保証する仕組みではない。

実機sessionは開始時に音対応を確認して消音、正常終了・停止・エラー終了でも消音する。新旧ファームで音を含まない作品の経路は維持する。画面の音のオン／オフは実機の音量には影響しない。

通常ランタイムのビルドは成功: bin 14,020 / 14,336 bytes、空き316 bytes、静的RAM444 bytes。以前の13,256 bytesから+764 bytes、RAM+12 bytes。容量制限と2つの作品バンク配置は変更していない。単独実行の音opcode追加はこの空きだけで進めず、容量整理を先に検討する。

[音とLED/NeoPixelの確認作品](../examples/blockly/piezo-led-preview.uiap.json)を追加。通常ランタイムの音・NeoPixel・USBの同時動作は、下記の確認作品で実機確認した。ファーム更新後もbytecodeの対応形式は1〜4で、音を含む作品はまだボードに保存できない。

2026-10-11: ユーザーの通常接続後、元の作品をファイルへ退避して確認作品を読み込み、「ボードでためす」を実行。UIはエラー表示なく実行完了へ戻った。ユーザーが「ラ」と同時に内蔵LED・NeoPixelが点灯し、消灯後に「高いド」が鳴り、最後に消音したことを確認した。この作品の範囲で、発音中に次の命令へ進む動作、LED・NeoPixelとの同時動作、音の置き換えと終了時の消音を確認できた。手動停止・通信切断・不正値などの実機確認まで完了した扱いにはしない。配線図の「1kΩ」「足の向きはどちらでもOK」は白いラベル枠へ変更し、画面で読みやすさを確認した。

- 部品の型番と定格、音階を出せる発振回路なしの圧電スピーカーかを確認する。

- D5（タクトスイッチ）、D8（NeoPixel）、内蔵LED、USBと競合しないPINを選ぶ。右側の配線のしやすさも考慮する。
